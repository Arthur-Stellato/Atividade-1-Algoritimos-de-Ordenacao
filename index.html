Quick Sort

Site-apresentação do seminário de Algoritmos de Ordenação: conceito, complexidade, comparação com o Bubble Sort e uma demonstração interativa com debugger de passos.

01O que é o Quick Sort

O Quick Sort é um algoritmo de ordenação por divisão e conquista: em vez de comparar tudo com tudo, ele escolhe um elemento como pivô, reorganiza o array para que os menores fiquem à esquerda e os maiores à direita, e repete o processo recursivamente em cada metade. É um dos algoritmos mais usados na prática, por ser rápido e ordenar o array no próprio lugar, sem precisar de memória extra proporcional ao tamanho da entrada.

02Como funciona, passo a passo

  1. Escolha do pivô — esta implementação usa sempre o último elemento da faixa como pivô (esquema de partição de Lomuto).
  2. Particionamento — o algoritmo percorre a faixa comparando cada elemento com o pivô: os menores vão para a esquerda, os demais permanecem à direita.
  3. Posicionamento do pivô — ao final da partição, o pivô é movido para a posição que já é definitiva no array ordenado.
  4. Recursão — o mesmo processo se repete, separadamente, na parte à esquerda e na parte à direita do pivô.
  5. Caso base — quando a faixa tem 0 ou 1 elemento, não há mais o que ordenar e a recursão para.

O pior caso acontece quando o pivô escolhido é sempre o menor ou o maior valor da faixa — por exemplo, um array já ordenado, já que aqui o pivô é o último elemento. Teste isso no campo de array customizado da demonstração: em vez de dividir o problema pela metade a cada chamada, o algoritmo passa a fazer só uma partição por vez, e a complexidade sobe para O(n²).

04Quick Sort vs. Bubble Sort

Os dois são algoritmos de comparação e troca, mas resolvem o problema de formas bem diferentes. O Bubble Sort percorre o array repetidamente, trocando pares adjacentes fora de ordem, até não haver mais trocas a fazer. O Quick Sort particiona o problema em torno de um pivô e ordena cada metade recursivamente — por isso escala muito melhor conforme o array cresce.

05Curiosidades

  • O Quick Sort foi criado por Tony Hoare em 1959, quando ele precisava ordenar palavras para um projeto de tradução automática russo-inglês — muito antes de boa parte das estruturas de dados que hoje consideramos básicas existirem.
  • Mesmo com pior caso O(n²), o Quick Sort costuma ser mais rápido na prática do que algoritmos com pior caso garantido O(n log n), como o Merge Sort, graças ao baixo overhead de memória e ao bom uso de cache do processador.
  • Bibliotecas padrão de várias linguagens usam variações otimizadas dele: o std::sort do C++ costuma usar introsort (Quick Sort combinado com Heap Sort e Insertion Sort), e o Java usa uma versão de dois pivôs para ordenar tipos primitivos.
  • Nem todo mundo usa Quick Sort puro: o Python ordena listas com Timsort, um híbrido de Merge Sort e Insertion Sort, justamente para evitar o pior caso O(n²).
  • O pior caso não é só teórico: já foi explorado como ataque de negação de serviço contra sistemas que ordenavam dados enviados por usuários com um pivô previsível. Por isso, implementações reais costumam escolher o pivô aleatoriamente ou usar a mediana de três valores.
